# Hassa Shop — Clean Rebuild

هذه نسخة مستقلة ونظيفة من متجر هسّا. لا تعتمد على واجهة أو API أو قاعدة بيانات المشروع القديم. الواجهة مبنية بالعربية وRTL، والـ API مبني داخل الخادم نفسه مع تخزين بيانات مستقل يبدأ من الصفر عند أول تشغيل.

## ما تم بناؤه

- واجهة متجر جديدة بالكامل بنفس الهوية البصرية المعتمدة: ألوان داكنة دافئة، لمسات طينية، خطا IBM Plex Sans Arabic وReadex Pro، ومساحات واضحة ومتجاوبة.
- كتالوج منتجات ومتاجر وأقسام.
- تسجيل دخول وإنشاء حساب للعميل بجلسة HttpOnly موقعة.
- حساب عميل مستقل مع الطلبات والمفضلة وبيانات الحساب والدعم.
- سلة محلية مرتبطة بالـ API عند تأكيد الطلب.
- إنشاء طلبات والتحقق من المتجر والمخزون وتخفيض الكمية بشكل ذري داخل عملية الطلب.
- مسارات فحص: `/api/health` و`/api/catalog` و`/api/auth/*` و`/api/orders` و`/api/favorites/*` و`/api/support`.

## التشغيل محليًا

```bash
pnpm install
pnpm check
pnpm build
PORT=3000 NODE_ENV=production pnpm start
```

يتم إنشاء ملف البيانات المحلي `server/data/store.json` تلقائيًا عند أول تشغيل، وهو غير مرفوع إلى Git. الحساب التجريبي الذي يتم إنشاؤه تلقائيًا هو:

- البريد: `tcust@hassa.com`
- كلمة المرور: `Pppqqqooo`

يجب تغيير هذا الحساب أو تعطيله قبل فتح النسخة الجديدة للعامة.

## الاسترجاع

الموقع القديم محفوظ بشكل مستقل في GitHub على الفرع `backup/pre-clean-rebuild` داخل مستودع `hassacom/hassa`. هذه النسخة النظيفة لا تعدل بيانات الموقع القديم ولا تستخدم API الخاص به.

## ملاحظة النشر

قبل ربط الدومين، يجب نشر هذه النسخة كخدمة جديدة أو كبيئة منفصلة، مع تخصيص تخزين دائم لمجلد `server/data` أو استبداله بقاعدة PostgreSQL مُدارة. لا ينبغي ربط الدومين القديم قبل اختبار تسجيل الدخول والكتالوج والطلب على رابط المعاينة الجديد.

## التخزين الدائم للصور على Railway

تم تجهيز رفع صور المنتجات عبر `POST /api/merchant/uploads` باستخدام حقل multipart باسم `images`. يقبل المسار حتى ست صور، وبحجم أقصى 8 ميجابايت للصورة، وبصيغ JPG وPNG وWEBP وGIF وAVIF. تحفظ الصور وتظهر عبر `/uploads/...`، كما أن الواجهة تستخدم هذا المسار مباشرة عند إنشاء المنتج.

لجعل التخزين دائمًا في Railway، أضف **Volume** إلى خدمة التطبيق واجعل نقطة تركيبه `/data`، ثم أضف متغيري البيئة التاليين:

```text
DATA_DIR=/data
UPLOAD_DIR=/data/uploads
```

بهذا تحفظ الخدمة ملف قاعدة البيانات المحلي والصور المرفوعة في نفس الـ Volume عبر عمليات النشر وإعادة التشغيل. من دون Volume سيعمل الرفع محليًا، لكن نظام ملفات Railway المؤقت لا يضمن بقاء الملفات.
